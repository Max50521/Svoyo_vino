# «Паспорт вкуса»: отчёт о реализации

Дата: 28.09.2026. Ветка: `feat/taste-passport` (от `main` @ `a1db82f`), в `main` не слито. Задание: [docs/CLAUDE_TASTE_FEATURES_PROMPT.md](../../docs/CLAUDE_TASTE_FEATURES_PROMPT.md).

Две функции карточки распознанного вина:

1. **«Какое оно на вкус»** — сладость, кислотность, танины, тело вина: три маркера + обязательная подпись, справка по термину, строка-резюме из подтверждённых фактов.
2. **«Ароматы и вкусовые ноты»** — до шести нот с оригинальными SVG-рисунками, раскрываемая карта семейств, исходная фраза по нажатию, блок «На чём основано».

Всё строится из названия и описания конкретной карточки детерминированным анализатором без сети, LLM, новой БД и без изменений распознавания.

## Браузерная проверка

`web/scripts/taste-browser-check.mjs` запускает headless Chrome против живого стенда:

- ширины **360, 390, 768, 1440**: нет горизонтального скролла, элементы паспорта не выходят за экран, подписи не обрезаны, подписи колеса внутри карточки, области нажатия ≥ 44 px;
- справка по термину, одна открыта за раз; нота → исходная фраза с подсветкой; карта: список на телефоне, колесо на широком экране; одна панель за раз; **Esc закрывает и возвращает фокус**; сектор колеса открывается с клавиатуры (Enter);
- «На чём основано», подпись «Ассоциации из описания вина, а не добавленные ингредиенты», ссылка `https://vino-svoe.ru/wines/{slug}`;
- неполная карточка, игристое, прямая ссылка + перезагрузка (SSR и гидратация дают одинаковый текст), 404;
- **реальное фото** с неуверенным распознаванием → предупреждение и кандидаты выше паспорта → переход к другому кандидату обновляет весь паспорт; фото вина вне каталога → `not_found`, паспорта нет;
- контраст текста паспорта ≥ 4.5:1; нет предупреждений гидратации и исключений в консоли.

Формат URL портала проверен запросами к vino-svoe.ru для 7 slug каталога (все 200) и несуществующего slug (404).

## Скорость и вес

- Анализатор: p50 0.15 мс, p95 0.31 мс на вино; весь каталог — 0.39 с (Node 24, один поток). В распознавании не участвует.
- Клиентские ресурсы (`.output/public/_nuxt`, js + css): `main` 222.7 КБ / 85.2 КБ gzip → ветка 250.3 КБ / 94.5 КБ gzip, то есть **+27.6 КБ (+9.3 КБ gzip)**. Библиотек графиков и новых зависимостей нет; рисунки — инлайновый SVG.

## Решения, отличающиеся от спецификации

- Модуль лежит в `web/server/taste/`, а не в `server/utils/`: так он не попадает в автоимпорт Nitro и импортируется явно; типы — в `web/types/taste.ts`, потому что клиентский tsconfig не видит `server/`.
- В новых компонентах `computed`/`ref` импортируются из `vue` явно: в этой установке автоимпорт Nuxt типизирует их как `any` (сгенерированный `.nuxt` ссылается на `vue/index` без типов), и строгая проверка типов в компонентах иначе не работает.
- Приглушённый текст паспорта использует `--text-muted` (#6e6863): токен портала `--text-2` даёт 3.9:1 — меньше требуемых 4.5:1 для мелкого текста.
- Обобщённая нота скрывается, если в том же семействе есть конкретная («Ягоды» рядом с «Вишней»); обобщения вроде «Тёмные ягоды», «Лесные ягоды» остаются.
- «Лёгкий вкус» не считается лёгким телом, а «вкус полный» — считается полным телом; «мягкая кислотность» — низкая (отмечено как спорное в ручной проверке).

## Что не проверено

- Linux и Docker-развёртывание: стенд — Windows + PGlite.
- Реальные мобильные устройства и Safari/iOS: проверено в эмуляции Chrome (DPR 2, mobile).
- Экранный диктор вживую: проверены роли, `aria-expanded`/`aria-pressed`/`aria-controls`, скрытые подписи уровня и порядок фокуса, но не озвучивание NVDA/VoiceOver.
- Фотографии страниц Wine Folly в задание не попали: визуальный язык построен по описанию приёмов в задании; изображения и схемы книги не использовались.
- Полнота словаря: 5 из 50 проверенных карточек содержат пропуск (редкие слова вроде «медоносы», «воск», «ладан»); на всём каталоге такие пропуски не подсчитаны.
- Совпадение slug и URL портала подтверждено на выборке из 7 карточек, не для всех 2080.

## Как запустить

```powershell
# стенд (после setup: .env, ml/.venv, data/, индекс)
.\scripts\start-local.ps1 -PortableDb -NodeExe 'C:\Program Files\nodejs\node.exe'   # http://127.0.0.1:8080
cd web
npm test                                   # 45 тестов
npx vitest run -c vitest.scripts.config.ts # покрытие → reports/taste-passport/coverage.json
node scripts/taste-browser-check.mjs       # браузерная проверка и скриншоты (нужен запущенный стенд)
```

Без полного стенда паспорт можно смотреть на stub-движке (`.\scripts\dev.ps1 -Stub`), но карточке всё равно нужна БД с таблицей `wines`.

## Сценарий демонстрации (2 минуты)

1. **0:00** Открыть http://127.0.0.1:8080 на телефоне (или в эмуляции 390 px) → «Выбрать из галереи» → фото этикетки из `eval/real/photos`.
2. **0:15** Карточка найденного вина: фото, винодельня, регион, сорт. Если распознавание неуверенное — сверху «Возможно, это» и «Не то вино?» с кандидатами; выбрать другого кандидата и показать, что паспорт сменился целиком.
3. **0:35** «Паспорт вкуса»: строка-резюме, четыре шкалы. Нажать «Кислотность ?» → справка. Показать шкалу с подписью «В описании не уточнено» — мы не выдумываем.
4. **0:55** «Ароматы и вкусовые ноты»: рисунки нот, подпись «Ассоциации из описания вина, а не добавленные ингредиенты». Нажать ноту → исходная фраза с подсветкой.
5. **1:15** «Раскрыть карту ароматов» → семейства; нажать семейство → ноты и цитаты; Esc закрывает. На широком экране — колесо с равными секторами.
6. **1:35** «На чём основано» → все выводы с цитатами из названия/описания.
7. **1:50** «Полная карточка на Своё Вино» → карточка этого вина на vino-svoe.ru.
