# Сканер российских вин «Своё вино» — пояснительная записка

Команда «Бешеные свинки» · кейс РСХБ.Цифра · версия `v1.1` · репозиторий: https://github.com/Max50521/Svoyo_vino

## 1. Задача и решение

Покупатель у полки не знает, что за российское вино перед ним: международные приложения таких вин не содержат, а этикетки одной винодельни похожи как близнецы. Кейс требует сервис, который по фото этикетки находит карточку вина в каталоге «Своё вино» настолько надёжно, чтобы сразу показывать одну карточку, а после поиска даёт пользователю дополнительную пользу.

Наше решение — веб-сервис с мобильным интерфейсом:

1. **Распознавание.** Фото нормализуется, SigLIP 2 превращает бутылку и две зоны этикетки в векторы, pgvector ищет ближайшие вина каталога, а текст этикетки (EasyOCR) переранжирует десятку кандидатов — так различаются вина одной серии, года и категории.
2. **Честный ответ.** Одна карточка, когда сервис уверен; «Возможно, это» и Top-5, когда нет; «нет в каталоге» с похожими винами, когда вино не найдено.
3. **После поиска.** «Паспорт вкуса» переводит описание вина на простой язык (сладость, кислотность, танины, тело, ароматы) с цитатой-источником у каждого вывода; «Похожие по вкусу» предлагают аналоги из других виноделен.

## 2. Стек

| Слой | Технологии |
|---|---|
| Интерфейс и API | Nuxt 3 (Vue 3, Nitro), TypeScript, OpenAPI 3.1 + Swagger UI |
| Распознавание | Python 3.12, FastAPI, PyTorch 2.11 (CUDA 12.8), SigLIP 2 `so400m-patch14-384`, EasyOCR (ru + en); опционально Yandex Vision OCR |
| Хранение и поиск | PostgreSQL 16 + pgvector (Docker) или PGlite — PostgreSQL + pgvector в WASM, без Docker |
| Паспорт вкуса и аналоги | детерминированный анализатор на TypeScript, без LLM и сети |
| Развёртывание | PowerShell-скрипты установки и запуска, Docker Compose (CPU / GPU), Bash-скрипты для Linux |
| Проверки | Vitest (61), pytest (58), браузерные проверки через Chrome DevTools Protocol (42), скрипт кейсодержателя |

## 3. Архитектура

```
телефон / браузер ──► web — Nuxt, :8080 ────────► ml — FastAPI, :8001
                        │  интерфейс, API, Swagger     нормализация → SigLIP 2 ‖ EasyOCR
                        │                              /rerank: Top-10 + текст → Top-5
                        ├──► PostgreSQL + pgvector: wines, wine_embeddings (3 вектора на вино)
                        └──► паспорт вкуса и аналоги: анализ описаний, профили каталога в памяти
```

Запрос `POST /v1/search`: проверка файла → `/analyze` (вектор + текст этикетки) → pgvector, визуальный Top-10 → `/rerank` → Top-5, статус, `confidence`; при `not_found` — аналоги по сорту с этикетки. Карточка `GET /v1/wines/:slug` добавляет `taste_passport`. Подробно — слои, контракт ML-сервиса, данные и оценка: [ARCHITECTURE.md](../ARCHITECTURE.md).

## 4. Развёртывание

**Требования:** Windows 10/11, Python 3.11+ (проверено 3.12), Node.js 20+ (проверено 24), 7-Zip, ~20 ГБ диска; NVIDIA GPU желательна (≈ 2,3 ГБ видеопамяти), без неё работает на CPU медленнее. Docker не обязателен.

```powershell
git clone https://github.com/Max50521/Svoyo_vino.git
cd Svoyo_vino
.\scripts\setup.ps1 -DatasetDir "C:\путь\Датасет" -PortableDb   # один раз; или -DatasetZip "...\Датасет.zip"; без GPU: -Cpu
.\scripts\start-local.ps1                                       # ждёт /ready → http://127.0.0.1:8080
.\scripts\stop-local.ps1
```

`setup.ps1` распаковывает датасет организаторов, ставит зависимости, собирает web, сопоставляет каталог с фото, строит индекс и загружает модели (SigLIP 2 ≈ 4,5 ГБ, EasyOCR ≈ 100 МБ; индекс на RTX 4060 — ~10 минут). Повторный запуск безопасен. Проверено с нуля на Windows 11 + RTX 4060.

Другие варианты:

- **Postgres в Docker Desktop:** `.\scripts\setup.ps1 -DatasetZip "...\Датасет.zip"` без `-PortableDb`.
- **Docker Compose целиком** (после построения индекса): `docker compose --profile full up -d --build`; с GPU — добавить `-f docker-compose.gpu.yml`.
- **Linux:** `bash scripts/setup-linux.sh --cuda /path/dataset.zip && bash scripts/start-linux.sh` — подготовлено, на реальной машине не проверялось.
- **Телефон в той же сети:** `http://<IP компьютера>:8080` — web слушает все интерфейсы; кнопка «Сфотографировать этикетку» открывает камеру телефона.

Переменные окружения — таблица в [README](../README.md#переменные-окружения), шаблон — [.env.example](../.env.example).

## 5. API

Интерактивная документация — **`http://127.0.0.1:8080/docs`** (Swagger UI, можно отправлять запросы прямо со страницы), спецификация — `/openapi.json`.

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/v1/eval/predict` | контракт скрипта кейсодержателя: фото → ровно `{"slug": "..."}` |
| `POST` | `/v1/search` | Top-1, Top-5, `status`, `confidence`; при `not_found` — `analogs`, `label_hints` |
| `GET` | `/v1/wines/:slug` | карточка вина с `taste_passport` |
| `GET` | `/v1/wines/:slug/analogs` | аналоги из других виноделен с объяснением |
| `GET` | `/v1/wines/:slug/similar` | похожие по визуальному сходству |
| `GET` | `/v1/wines/:slug/image` | фото из каталога |
| `GET` | `/v1/metrics` | измеренное качество с описанием набора данных |
| `GET` | `/health`, `/ready` | состояние и готовность |

```bash
curl -F image=@eval/queries/019c68d0.jpg http://127.0.0.1:8080/v1/eval/predict
# {"slug":"pino-nuar-2025"}
```

Фрагмент реального ответа `POST /v1/search` на фото организаторов `eval/queries/019c68d0.jpg`:

```json
{
  "top1": { "slug": "pino-nuar-2025", "name": "Пино Нуар, 2025", "winery": "Винодельня Братьев Мельниковых", "score": 0.7399 },
  "top5": [ "…" ],
  "status": "not_found",
  "confidence": { "top1": 0.7399, "top5": [0.7399, 0.7184, 0.7172, 0.7167, 0.7162], "gap_top2": 0.0215, "gap_top5": 0.0237,
                  "visual_top1": 0.714, "thresholds": { "confidence_margin": 0.05, "not_found_score": 0.75 } }
}
```

Здесь лучшее визуальное сходство 0,714 ниже порога 0,75, поэтому интерфейс показывает «нет в каталоге» и похожие вина, а `/v1/eval/predict` всё равно возвращает лучший slug — `pino-nuar-2025`, как требует контракт скрипта.

`confidence` — метрика уверенности каждого ответа для Top-1 и Top-5: скоры и отрывы. Это значения ранжирования, а не вероятность и не F1; измеренные Top-k и F1 отдаёт `/v1/metrics`. Ошибки: `{"error": "..."}` — 400, 404, 413 (> 15 МБ), 503.

## 6. Метрики

Публичный набор организаторов: 100 полевых фото, разметка командой (использовался при разработке; закрытой разметки организаторов нет).

| Метрика | Значение |
|---|---|
| Top-1, 64 фото вин из каталога | **59 / 64 — 92,19 %** |
| Top-5 | **64 / 64 — 100 %** |
| micro-F1 Top-1, 56 фото с единственным верным slug | 0,9107 |
| Верный «нет в каталоге», 33 фото вин вне каталога | 19 / 33 |
| Ответы со статусом «уверен» | верны в 32 из 33 |
| Скрипт кейсодержателя, 100 фото | 100 валидных slug, p50 / p95 — 685 / 970 мс (RTX 4060) |

Вклад компонентов в Top-1 / Top-5: только изображение — 71,9 % / 96,9 %; + чтение этикетки — 84,4 % / 98,4 %; + сорт и смешанные алфавиты — 92,2 % / 100 %. Разбор пяти ошибок Top-1 и проверки устойчивости — [docs/TOP1_ACCEPTANCE.md](TOP1_ACCEPTANCE.md).

## 7. Функция после поиска

| Блок | Что видит пользователь |
|---|---|
| «Какое оно на вкус» | сладость, кислотность, танины, тело — три маркера и слово, справка по термину; своя шкала для игристых |
| «Ароматы и вкусовые ноты» | до 6 нот с оригинальными рисунками, карта из 13 семейств (колесо на ПК, список на телефоне) |
| «На чём основано» | цитата из описания карточки у каждого вывода |
| «Похожие по вкусу — другие винодельни» | тот же цвет и стиль, общий сорт или ноты, по одному вину на винодельню, с объяснением общими фактами |
| «Нет в каталоге» | похожие по этикетке + аналоги по сорту, прочитанному на этикетке |

Правило достоверности: источник — только название и описание карточки; ничего не выводится из сорта, региона или фото, нет «процентов уверенности». Нет факта — «В описании не уточнено».

Качество на всём каталоге (2 103 вина): ноты ароматов с цитатой — у 2 073, аналоги — у 2 071; шкалы по явным словам — сладость 373, кислотность 290, тело 181, танины 68. Ручная проверка 50 разнородных карточек — 0 ложных находок, 43 без замечаний. Анализ — 0,15 мс на вино, подбор аналогов — ~1 мс. Подробно: [reports/taste-passport/REPORT.md](../reports/taste-passport/REPORT.md).

## 8. Устойчивость и безопасность

- Ограниченная очередь распознавания: при перегрузке — 503, сервис не падает; OCR с таймаутом, при сбое остаётся визуальный результат.
- `/ready` проверяет совпадение модели, размерности и полноту индекса; хеши исходных фото и кода защищают от устаревших векторов.
- Загружаемые фото проверяются по сигнатуре, ограничены 15 МБ и обрабатываются в памяти — на диск не сохраняются.
- Сбой паспорта вкуса или аналогов не ломает карточку и поиск.
- В репозитории нет датасета, весов, `.env` и личных фото.

## 9. Ограничения

- Точности измерены на публичном наборе с командной разметкой; закрытой оценки ещё не было.
- «Нет в каталоге» — 19 из 33; 5 ошибок Top-1 — близкие вина одной линейки (верный ответ есть в Top-5).
- Аналоги для вина вне каталога появляются, только если OCR прочитал сорт (на публичных фото — 2 из 25 ответов `not_found`).
- Шкалы вкуса заполнены только там, где описание говорит об этом явно; рейтинга Роскачества и гастросочетаний нет в данных — ссылка ведёт на полную карточку портала.
- Проверенный стенд — Windows + GPU; Linux и Docker Compose подготовлены, но не прогонялись на реальной машине. Swagger UI загружает оформление с CDN jsDelivr (нужен интернет в браузере; `/openapi.json` работает офлайн).
